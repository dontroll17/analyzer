# Stream Sensation Analyzer

> Расширение Chrome (Manifest V3) для анализа аудиопотока в реальном времени и обнаружения аномалий генеративных аудиосистем.

## Возможности

| Модуль | Описание | Статус |
|--------|----------|--------|
| **Захват аудио** | Перехват звука активной вкладки через `getDisplayMedia` | ✅ Реализовано |
| **RMS анализ** | Расчёт энергии сигнала в реальном времени через AudioWorklet | ✅ Реализовано |
| **Спектральный анализ** | FFT с разбиением на 3 частотных диапазона (Bass / Mid / Treble) | ✅ Реализовано |
| **Детектор глитча** | Обнаружение ВЧ-аномалий (>12 кГц) с state machine и debounce | ✅ Реализовано |
| **Осциллограф** | Визуализация волны в реальном времени (2 канала, Canvas) | ✅ Реализовано |
| **Экспорт данных** | Сохранение осциллограммы в CSV | ✅ Реализовано |
| **Чувствительность** | Настройка порогов детектора глитча через UI (слайдер 60–90%) | ✅ Реализовано |
| **Экспорт лога** | Сохранение лога глитчей в JSON (FIFO, max 500 записей) | ✅ Реализовано |
| **Sensation State** | Визуальный индикатор (STABLE / DRIFT / GLITCH) с цветным кружком | ✅ Реализовано |
| **Спектральная энтропия** | Анализ равномерности распределения энергии по спектру | 📋 В плане |
| **Overlay-виджет** | Плавающий Canvas-виджет поверх веб-страницы | 📋 В плане |

## Установка

1. Откройте Chrome и перейдите на страницу `chrome://extensions`
2. Включите **Режим разработчика** (Developer mode) в правом верхнем углу
3. Нажмите **\"Загрузить распакованное расширение\"** (Load unpacked)
4. Выберите папку `c:\analyzer`

## Использование

### Запуск захвата

1. Откройте страницу с аудиопотоком (YouTube, Spotify и т.д.)
2. Активируйте вкладку с воспроизведением звука
3. Нажмите на значок расширения в панели инструментов
4. Нажмите **\"Start Capture\"** в popup-окне

> **Примечание:** используется `getDisplayMedia` с флагом `preferCurrentTab: true` — достаточно поделиться текущей вкладкой в диалоге системы захвата экрана.

### Управление

| Действие | Описание |
|----------|----------|
| **Start Capture** | Запуск захвата и анализа аудио |
| **Stop Capture** | Остановка захвата, очистка буферов |

### Интерфейс popup

В popup отображаются:
- **RMS Level** — текущая энергия сигнала с цветовой индикацией
- **Frequency Bands** — распределение энергии по диапазонам (Bass / Mid / Treble)
- **Glitch Sensitivity** — слайдер настройки порога детектора (60–90%, по умолч. 85%)
- **Sensation State** — индикатор состояния: STABLE (зелёный) / DRIFT (оранжевый) / GLITCH (красный)
- **Осциллограф** — визуализация волны в реальном времени (2 канала, Canvas)
- **Export CSV** — сохранение данных осциллограммы в CSV
- **Export Log** — сохранение лога глитчей в JSON (до 500 записей)

## Проверка работы

1. Откройте **DevTools** (F12 → Console) на странице с аудио
2. Запустите захват из popup
3. Ожидаемые логи:

```
Stream Sensation Analyzer installed/updated
AudioAnalyzer initialized with sampleRate: 44100
Frequency bands: 45.23% 38.12% 16.65%
```

### Что проверить

| Метрика | Ожидание |
|---------|----------|
| **RMS Value** | Меняется в зависимости от громкости аудио (0.0 — 1.0) |
| **Frequency Bands** | Сумма Bass + Mid + Treble ≈ 100% |
| **Осциллограф** | Отображает форму волны в реальном времени |

## Технические детали

### DSP Engine (`dsp-engine/audio-worklet.js`)

| Метод | Описание |
|-------|----------|
| `calculateRMS(buffer)` | Средняя квадратичная энергия сигнала |
| `calculateFFT(buffer, numBins)` | DFT с заданным количеством бинов |
| `calculateFrequencyBands(fftData)` | Разложение на Bass (0–220 Гц), Mid (220–4400 Гц), Treble (4.4–22 кГц) |
| `detectHighFrequencyAnomaly(fftData)` | Отношение энергии ВЧ (верхняя четверть спектра) к общей энергии |
| `checkGlitchState(rms, highFreqRatio)` | State machine: STABLE → DRIFT → GLITCH |
| `port.onmessage(event)` | Обработка сообщений из main thread (`SET_GITCH_CONFIG`) |

### Параметры детектора глитча

| Параметр | Значение | Описание |
|----------|----------|----------|
| `highFreqThreshold` | 0.85 (настраивается) | Порог ВЧ-энергии (60–90%, настр. через UI) |
| `minTotalEnergy` | 0.04 | Минимальная энергия (игнорировать тишину) |
| `debounceTimeout` | 800 мс | Задержка между срабатываниями |
| `driftThreshold` | 0.70 | Порог DRIFT (бывш. WARNING) |
| `requiredConsecutiveFrames` | 2 | Требуемые кадры аномалии подряд |

### Sensation State (State Machine)

| Состояние | Цвет | Описание |
|-----------|------|----------|
| **STABLE** | 🟢 зелёный | Нормальная работа, энергия ниже DRIFT-порога |
| **DRIFT** | 🟠 оранжевый | Повышенная ВЧ-энергия (между driftThreshold и highFreqThreshold) |
| **GLITCH** | 🔴 красный | Аномальная ВЧ-энергия (> highFreqThreshold, несколько кадров подряд) |

### RMS классификация

| Уровень | Диапазон | Цвет |
|---------|----------|------|
| SILENCE | < 0.01 | `#ff6b6b` (красный) |
| LOW | 0.01 – 0.1 | `#ffa94d` (оранжевый) |
| MEDIUM | 0.1 – 0.3 | `#95df6c` (зелёный) |
| HIGH | 0.3 – 0.7 | `#3ac7a3` (бирюзовый) |
| CRITICAL | > 0.7 | `#d9363e` (тёмно-красный) |

### Ограничения текущей версии

- ✅ Настройка чувствительности глитч-детектора через UI (слайдер 60–90%)
- ✅ Экспорт лога глитчей в JSON (FIFO, max 500 записей)
- ✅ Визуальный индикатор Sensation State (STABLE / DRIFT / GLITCH)
- ❌ Нет спектральной энтропии
- ❌ Нет overlay-виджета поверх страницы
- ⚠️ Настройки чувствительности НЕ сохраняются между сессиями (сброс к 85%)
- ⚠️ Аудиопоток не воспроизводится (только анализ) — во избежание обратной связи
- ⚠️ Oscilloscope использует аппроксимацию формы волны на основе RMS
- ⚠️ Popup закрывается при клике вне его области (ограничение Chrome)

## Решение проблем

| Проблема | Решение |
|----------|---------|
| `Tab capture error: Access denied` | Убедитесь, что расширение вызывается из popup; вкладка активна; на ней воспроизводится звук |
| `Permission denied` | Перезагрузите расширение на `chrome://extensions` |
| Нет данных в консоли | Убедитесь, что нажата кнопка \"Start Capture\" и консоль открыта |
| AudioWorklet не загружается | Проверьте консоль на ошибки загрузки модуля; убедитесь, что `dsp-engine/audio-worklet.js` существует |
